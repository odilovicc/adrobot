# Adrobot — дизайн (2026-11-17)

Источник требований: ТЗ «Adrobot — ТЗ для Claude Code» (claude.ai artifact). Здесь — только решения,
принятые поверх ТЗ, и закрытые в нём дыры.

## Стек и окружение
- Python ≥ 3.12 через `uv`; FastAPI + SQLAlchemy 2.0 (sync, SQLite по умолчанию) + Alembic + httpx.
- Фронт: Jinja2 + Bootstrap 5 + jQuery + Select2 (CDN). Мутации возвращают HTML карточки потока.
- `make dev` поднимает app (:8000) и mock Keitaro (:8100); `docker-compose.yml` — альтернатива.

## Доменная логика — уточнения
1. **Порядок округления.** Остаток `rem` раздаётся первым незакреплённым офферам в порядке `position`
   привязки (порядок из Keitaro, новые — в конец). Результат детерминирован: 75/2 → 38+37.
2. **Ручной ввод веса** = pin с этим значением. Если сумма pinned > 100 — 400, в БД ничего не меняется.
3. **Pin removed-оффера запрещён**; Remove и Bring back сбрасывают pin.
4. **Все закреплены, сумма ≠ 100** — состояние допустимо, но Push заблокирован, сумма в заголовке красная.
5. **Защита от гонки при Push.** Перед `PUT` читаем поток из Keitaro и сравниваем офферы с последним
   опубликованным снимком. Если кто-то поменял поток в трекере после Fetch — 409
   «Поток изменён в Keitaro, сделайте Fetch», ничего не перезаписываем.
6. **Состояние оффера в потоке Keitaro** (`active`/`disabled`) сохраняется в `kt_state` и отправляется
   обратно как было — Push не включает выключенные в трекере офферы.
7. **Fetch при наличии черновиков** — подтверждение в Bootstrap-модалке (не `confirm()`).
8. **Создаватор:** alias до 3 попыток при коллизии; оффер и гео проверяются до любого запроса на запись;
   любая ошибка после `POST /campaigns` → `DELETE /campaigns/{id}`.

## Проверка реального API
`scripts/probe_keitaro.py`: GET справочников + `/streams_actions`, затем временная кампания
`adrobot-probe-*` с двумя потоками, `PUT /streams/{id}` только с `offers`, проверка, что фильтры и
`action_payload` не сбросились, удаление кампании. Итог — в README, mock повторяет подтверждённое поведение.

## Тесты
- `weights`: таблица кейсов из ТЗ + property-тесты (hypothesis): сумма = 100, pinned неизменны,
  разброс незакреплённых ≤ 1.
- Сервисы и HTTP: сценарий из видео по шагам против mock (`TestClient(mock_app)` как транспорт httpx).
- Создаватор: успех, валидация, откат при сбое создания потока (инъекция ошибки в mock).
